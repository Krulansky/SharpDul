# SharpDul (#Dul) - Agent Instructions

Read this first, then `PROJECT_STATE.md` (where we are) and `DESIGN_BRIEF.md` (the app).
`GAMEDEVNOTES.md` is the **travelling notebook** of general game-design, game-feel and Unity
lessons from every project (moved here from FerryHeist on 2026-10-26). Whenever any project
learns something that would apply to any game, add an entry there. `knowledge/` holds notes
about one source project each. This file is in the repository on purpose:
it is the only context that reaches every machine. Do not rely on memory from other sessions.

## What this is

**SharpDul** is the director's personal gamedev coach: spaced-repetition quizzes and live labs
built from their own game projects (LuaLander, FerryHeist, ...). Two parts:

- **SharpDul Pocket** - Blazor WebAssembly PWA in C#, installed on the iPhone from Safari.
  There is no Mac, so no native iOS build.
- **SharpDul Playground** - a Unity `6000.3.14f1` project for the Windows PCs (particles, UI, 3D).

## Roles

- **The user is the director.** They decide design and review the result.
- **The agent implements.** Surface every *design* decision; routine technical choices can be
  made and stated in one line.

## Language

The user writes casual Slovak mixed with English gamedev terms - answer in the same blend.
**Code, identifiers, comments, commit messages and all repo docs stay English.**

## How the user wants to be worked with

- Say exactly where: full file paths, full click paths, full Hierarchy paths.
- Do not claim success before the director has seen it work.
- Flag a concern once; after the decision, do not re-raise it.
- Diagnose from evidence and label hypotheses as hypotheses.
- Walk through any deletion with the user first.

## Content rules

- Questions are generated by the agent from the source projects and committed as JSON
  content packs. Every question cites its source file and lines.
- Easy level never uses fill-in, find-the-bug or write-the-function questions.
- **The code must lead to the answer.** Every question has a plain-language `context` (where
  the code lives, when it runs in the game), a trimmed snippet in which the answer can be
  found, `highlight` on the lines that hold it, and a `hint` that says what to look at
  without giving the answer. Ask in game terms ("you land at speed 5 - what happens?"),
  not in jargon. Director feedback 2026-10-26: snippets that had nothing to do with the
  answer made the first version too hard.
- **Languages: EN, SK, KR (Korean).** English is the source (`<pack>.json`); translations
  live in `<pack>.sk.json` / `<pack>.ko.json` and must cover every question. UI text is in
  `Localization/Strings.cs`. **Gamedev terms stay English in every language** (event,
  singleton, particles, landing pad, Burst, XP, Level, ...); code is never translated.
- Progress uses **active days**, never a breakable streak. No deadline pressure.
- The app holds no API keys and does no tracking.
- Visual identity (logo, colours, fonts) belongs to the director. Use neutral placeholders
  and never invent branding.
